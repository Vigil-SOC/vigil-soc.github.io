## Case Management

Full investigation lifecycle tracking.

### Case Tabs

| Tab | Purpose |
|-----|---------|
| Summary | Case overview and decision |
| Explanations | Investigation explanations (hypotheses) |
| Evidence | Evidence collected for the case |
| Checked | Checks performed during the investigation |
| Memory and blind spots | Recalled memory and blind spots / gaps |
| Record | Case record rows |

### Case Status Flow

```
new -> open -> investigating -> closed
```

### Resolution Steps

Document each resolution step with:
1. **Description**: What was done
2. **Action Taken**: Detailed explanation
3. **Result**: Outcome
4. **Timestamp**: Auto-recorded

### Board Brief

One-page risk posture report designed for boards and CEOs. Triggered by saying "Generate board brief" or "Create board report" in the Vigil chat.

| Section | Contents |
|---------|----------|
| Risk posture | Red/yellow/green indicator with one-line summary |
| Key metrics | Validated kill chains, detection coverage %, MTTR, open criticals |
| Top 3 action items | Each with risk description, fix type (budget/policy/technical), and impact |
| 30/60/90 day trend | Exposure count direction — improving, stable, or degrading |

The board brief uses non-technical language throughout — no CVE numbers or ATT&CK IDs in the main body. All metrics are pulled from actual findings and case data.

The template lives in the Vigil product repo at `core/skills/library/executive-summary/assets/board-brief.md`. Output is markdown in chat, with a note in the skill that PDF export is available.

**Quick commands:**
- "Generate board brief"
- "Create board report for last 30 days"
- "Generate risk posture report"

## Approval Workflow

Human-in-the-loop for autonomous actions.

### Confidence Thresholds

All actions require human approval. No confidence band auto-approves: a confidence never marks a row approved, and every class waits for a human. The thresholds below are routing / prompt bands only.

| Confidence | Routing band |
|------------|--------------|
| >= 0.90 | Requires approval |
| 0.85-0.89 | Quick review — requires approval |
| 0.70-0.84 | Human review — requires approval |
| < 0.70 | Monitor only |

### Force Manual Approval

There is no Dashboard > Approval Queue checkbox. To require asking first, use the Ask/Act autonomy control in **Settings > Limits & autonomy**: set the relevant actions to **Ask first** instead of **On their own**.

Use when:
- Training/testing environment
- During active incidents
- New deployment (first weeks)
- Compliance requirements

### Action Types

- `isolate_host` - Network isolate compromised host
- `block_ip` - Block malicious IP
- `block_domain` - Block malicious domain
- `quarantine_file` - Quarantine malicious file
- `disable_user` - Disable compromised account
- `execute_spl_query` - Run Splunk query
- `workflow_phase` - Workflow phase with approval required
- `promote_rule` - Promote a rule from shadow to live
- `deploy_rule` - Open a live rule's deploy PR
- `waf_block` - Cloudflare WAF IP Access Rule
- `gateway_block` - Cloudflare Zero Trust Gateway DNS/HTTP rule
- `access_revoke` - Cloudflare Zero Trust Access session revoke
- `custom` - Custom action

## AI Finding Enrichment

AI analysis stored with the finding.

### Enrichment Contents

| Field | Description |
|-------|-------------|
| Threat Summary | Clear overview of the threat |
| Threat Type | Classification (exfiltration, lateral movement, etc.) |
| Risk Level | Critical, High, Medium, Low |
| Potential Impact | Business impact explanation |
| Recommended Actions | Prioritized response steps |
| Investigation Questions | Key questions for deeper analysis |
| Related Techniques | MITRE ATT&CK mapping |
| Indicators of Compromise | Malicious IPs, domains, processes |
| Confidence Score | AI's confidence (0-100%) |

### Usage

1. Open any finding detail view
2. Enrichment is served as stored data (`finding.ai_enrichment`), pre-computed by the pipeline / `scripts/enrich_findings.py` — it is not generated by opening a finding
3. Cached in database for instant retrieval

No force-regeneration button was found in the current finding UI.

## Autonomous Response

Auto-Responder agent for automated containment.

### Multi-Source Correlation

1. Pull alerts from Tempo Flow (network)
2. Pull alerts from EDR (e.g. CrowdStrike) (endpoint)
3. Correlate by IP, time, behavior
4. Calculate confidence score
5. Queue action for approval based on threshold

### Confidence Calculation

| Factor | Points |
|--------|--------|
| Multiple corroborating alerts | +0.20 |
| Critical severity | +0.15 |
| Lateral movement | +0.15 |
| Known malware | +0.20 |
| Active C2 | +0.20 |
| Ransomware behavior | +0.25 |
| Time correlation | +0.10 |

### Example Flow

```
1. Detect suspicious IP
2. Query Tempo Flow -> Lateral movement detected
3. Query EDR -> Ransomware behavior
4. Calculate confidence: 0.85
5. Queue isolation for approval
6. Report to analyst
```

Note: `isolate_host` execution is not wired to an EDR executor. The isolation executor returns `unsupported_action_type` ("No EDR executor is configured for host isolation"), so an approved isolation does not execute a containment call.

## MITRE ATT&CK Integration

### Technique Rollup

- Count findings per technique
- Sort by prevalence
- Filter by time window
- When a run is selected, the rollup returns per-technique verdicts for that run

### Backend Tools

| Tool | Description |
|------|-------------|
| `get_technique_rollup` | Technique statistics |

`get_findings_by_technique` is not a backend tool; it is a REST route: `GET /api/attack/techniques/{technique_id}/findings`.
